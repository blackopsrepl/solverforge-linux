# SolverForge Linux Skill

Manage [SolverForge Linux](https://solverforge.com) systems — a coherent configuration framework for an openSUSE Sway desktop, modeled after a "Ruby on Rails-like" layered architecture. Immutable defaults, beautiful symlink wiring, single source of truth.

This skill describes SolverForge Linux `1.2.0`. Re-derive specifics from the framework checkout when the installed version differs.

## When This Skill MUST Be Used

**ALWAYS invoke this skill when the user's request involves ANY of these:**

- Editing ANY file under `~/.local/share/solverforge/`
- Editing ANY file in `~/.config/sway/`, `~/.config/waybar/`, `~/.config/wofi/`
- Editing terminal configs (`~/.config/kitty/`)
- Editing GTK/Qt/KDE configs (`~/.config/gtk-3.0/`, `~/.config/gtk-4.0/`, `~/.config/qt5ct/`, `~/.config/qt6ct/`, `~/.config/kdeglobals`)
- Editing shell configs (`~/.zshrc`, `~/.zsh/`, zsh files)
- Theme, color, font, or appearance changes
- Any `solverforge-*` command
- Adding new applications to the menu system
- Installing or removing packages
- Wiring new config files through the framework

**If you're about to edit a config file in ~/.config/ on this system, STOP and check if it's managed by SolverForge first.**

## Critical Rules

### Product Naming
- **"SolverForge Linux"** in README/docs. **"SolverForge"** by itself is their other product.
- **NEVER** use "omarchy" anywhere. SolverForge Linux was inspired by omarchy but is a separate product.

### Non-Negotiable Behaviors
- **NEVER use sed for config/code files** — always read, understand, rewrite whole with proper write tools.
- **NEVER rewrite files from memory** — always read the current file content first. User was burned by this.
- **NEVER fake migrations** — when moving files, use `mv` or `cp` from the actual file, never recreate from memory.
- **NEVER deflect or redirect** — when caught making an error, admit it immediately.
- **No shortcuts, no bandaids** — wire everything methodically, DHH Rails-style.
- **Propose "spiffiest" not "easiest"** — architecturally clean solutions.
- **Single source of truth** — e.g. floating window size set in `rules.conf` ONLY, not per-launch.
- **No figlet** — user explicitly rejected it.
- **Package manager is zypper** — openSUSE, not Arch. Never use pacman, yay, or apt.
- **Fonts must be Fira Code everywhere** — kitty, GTK, Qt, KDE/kdeglobals, waybar, wofi. Not Noto Sans, not Arial.
- **"Beautiful linking" means**: template in `default/theme/templates/` → generated by `solverforge-theme-apply` → symlinked from `~/.config/` → app reads it. No copies. No direct edits in `~/.config/`.
- **DO NOT run unnecessary diagnostic commands** — if confirmed working, leave it alone.
- **DO NOT test after deploying working code** — when user confirms something works, deploy and move on.

### Template Engine: `solverforge-theme-apply`

Three phases:

**Phase 1 — Generate:**
1. Copies static overrides from `overrides/` → `generated/` (they take precedence)
2. Reads `colors.toml`, builds sed substitution script with three variant forms:
   - `{{ variable }}` → `#hex` (e.g., `{{ accent }}` → `#82FB9C`)
   - `{{ variable_strip }}` → `hex` without # (e.g., `{{ accent_strip }}` → `82FB9C`)
   - `{{ variable_rgb }}` → `R,G,B` decimal (e.g., `{{ accent_rgb }}` → `130,251,156`)
3. Processes all `.tpl` files → `generated/` (skips if override already exists)

**Phase 2 — Wire:**
Symlinks from `~/.config/` → `generated/`:

| Generated File | Symlink Target | Notes |
|---|---|---|
| `kitty.conf` | included by `~/.config/kitty/kitty.conf` | via `include` directive |
| `sway-colors.conf` | included by sway orchestrator | via `include` directive |
| `gtk-colors.css` | `~/.config/gtk-{3,4}.0/colors.css` | `@import`'d by gtk.css |
| `gtk3-settings.ini` | `~/.config/gtk-3.0/settings.ini` | symlink |
| `gtk4-settings.ini` | `~/.config/gtk-4.0/settings.ini` | symlink |
| `qt5ct-hackerman.conf` | `~/.config/qt{5,6}ct/colors/hackerman.conf` | symlink (same file for both) |
| `kdeglobals` | `~/.config/kdeglobals` | symlink |
| `hackerman.colors` | `~/.local/share/color-schemes/hackerman.colors` | symlink (KDE color scheme) |
| `kdedefaults-kdeglobals` | `~/.config/kdedefaults/kdeglobals` | symlink (overrides openSUSE LnF) |
| `btop.theme` | `~/.config/btop/themes/hackerman.theme` | symlink |
| `lazygit.yml` | `~/.config/lazygit/config.yml` | symlink |
| `yazi-theme.toml` | `~/.config/yazi/theme.toml` | symlink |
| `mc-hackerman.ini` | `~/.local/share/mc/skins/hackerman.ini` | symlink |
| `delta.gitconfig` | included by `~/.gitconfig` | via `[include]` directive |
| `fzf.env` | sourced by `solverforge-env.zsh` | via `source` |
| `eza.env` | sourced by `solverforge-env.zsh` | via `source` |
| `swaylock.conf` | via `$SWAYLOCK_CONFIG` env var | set in environment.d |
| `swaync.css` | **copied** to `~/.config/swaync/style.css` | swaync can't follow symlinks |

Special: `plasma-apply-colorscheme hackerman` runs to activate the KDE color scheme via DBus.

**Phase 3 — Reload** (with `--reload` flag):
```
killall -SIGUSR1 kitty     # Kitty re-reads config
swaymsg reload              # Sway reloads
pkill -SIGUSR2 btop         # Btop re-reads theme
killall -SIGUSR2 opencode   # Opencode re-reads theme
swaync-client --reload-css  # SwayNC reloads CSS
```

### How to Add a New Themed App

This is the canonical pattern — follow it exactly:

1. **Create template**: `default/theme/templates/<appname>.tpl` using `{{ variable }}`, `{{ variable_strip }}`, or `{{ variable_rgb }}` substitutions
2. **Add symlink wiring** in `solverforge-theme-apply` Phase 2:
   ```bash
   wire_symlink "$GENERATED_DIR/<appname>" "$HOME/.config/<app>/path/to/config"
   ```
3. **Run** `solverforge-theme-apply` — the `for tpl in *.tpl` loop auto-discovers new templates
4. **Add reload command** in Phase 3 if the app supports live reload

**Exceptions to symlinks:**
- Apps that can't follow symlinks get `cp` instead (swaync is the only current case)
- Apps that use `include` or `source` directives (kitty, sway, git, zsh) — the generated file is included/sourced, not symlinked as the main config
- KDE color scheme activation requires `plasma-apply-colorscheme hackerman` after wiring

### Template Variable Reference

For a color like `accent = "#82FB9C"`:
- `{{ accent }}` → `#82FB9C` (for CSS, kitty, yazi, lazygit, mc — apps that want `#hex`)
- `{{ accent_strip }}` → `82FB9C` (for Qt5ct `#ffRRGGBB` format)
- `{{ accent_rgb }}` → `130,251,156` (for KDE kdeglobals `R,G,B` format)

### Override Semantics

Static files in `default/theme/overrides/` take precedence over templates. Currently used for `btop.theme` which has a complex format not suited to simple sed templating.

1. Add icon+name to `entries` string: `entries="<icon>  Name\n$entries"`

## Qt/KDE Theming — Hard-Won Knowledge

### The Pipeline
- `QT_QPA_PLATFORMTHEME=kde` — tells Qt to use KDE platform theme plugin, which reads kdeglobals
- `kdeglobals` — symlink to generated file, contains all KDE colors (RGB decimal), fonts (Fira Code), icons
- `hackerman.colors` — standalone KDE color scheme file, symlink to generated, contains ONLY color sections
- `kdedefaults/kdeglobals` — overrides openSUSE look-and-feel cascade (which forces BreezeClassic)
- `plasma-apply-colorscheme hackerman` — activates the scheme (updates caches, sends DBus signals)

### Critical Discoveries
- KDE apps read `kdeglobals` directly via KDE Frameworks, NOT through qt5ct
- `QT_QPA_PLATFORMTHEME=qt5ct` forces Fusion style + qt5ct palette, bypassing KDE color system entirely
- `QT_QPA_PLATFORMTHEME=kde` loads `KDEPlasmaPlatformTheme6.so` which reads kdeglobals properly
- `qt5ct-hackerman.conf` uses `#ffRRGGBB` format (alpha prefix), not plain `#RRGGBB`
- `kdeglobals` uses `R,G,B` decimal format (e.g., `11,12,22`), uses `{{ variable_rgb }}`
- openSUSE's `~/.config/kdedefaults/kdeglobals` forces `ColorScheme=BreezeClassic` — must be overridden
- `hackerman.colors` must be a standalone file with ONLY color sections — not a copy of full kdeglobals
- KDE System Settings reads kdeglobals directly as a config editor — it doesn't prove apps will use the colors
- Breeze style computes hover fills by blending DecorationHover at ~20% opacity — can't make neon hovers
- All KDE apps (Dolphin was removed, but others remain) are Qt6 linking against libQt6

### GTK Pipeline
- `colors.css` — symlink to `generated/gtk-colors.css`, `@import`'d by `gtk.css` in both gtk-3.0 and gtk-4.0
- `settings.ini` — symlink to `generated/gtk{3,4}-settings.ini` (gtk-3.0 has 3 extra keys: `button-images`, `menu-images`, `toolbar-style`)
- Theme: `Adwaita-dark` (not Breeze)
- Font: `Fira Code, 10`

## Decision Framework

When the user requests system changes:

1. **Is it a color/theme change?** → Edit `colors.toml`, re-run `solverforge-theme-apply`
2. **Is it a new app to theme?** → Create `.tpl` template, wire symlink in `solverforge-theme-apply`, run it
3. **Is it a shell change?** → Edit the appropriate `solverforge-*.zsh` file in `default/zsh/`
4. **Is it a sway change?** → Edit the appropriate file in `default/sway/`
5. **Is it a menu change?** → Edit `solverforge-menu` in `bin/`
6. **Is it a new script?** → Create `solverforge-<name>` in `bin/`, make executable
7. **Is it a package install?** → `sudo zypper install <package>` (NEVER pacman)
8. **Is it a font change?** → Update Fira Code references in kdeglobals.tpl, gtk templates, qt5ct, kitty
9. **Does it need an env var?** → Add to `~/.config/environment.d/solverforge.conf`

## Example Requests

- "Change the accent color" → Edit `colors.toml`, run `solverforge-theme-apply --reload`
- "Add lazygit to the menu" → Add entry + case to `show_tui_menu()` in `solverforge-menu`
- "Theme a new app" → Create `.tpl`, add `wire_symlink` in theme-apply, add reload if needed
- "Add a keybinding" → Edit `default/sway/bindings.conf` or `default/zsh/solverforge-keybindings.zsh`
- "Install a package" → `sudo zypper install <pkg>`, add to `default/dependencies.txt`
- "Change the font" → Update ALL templates that reference font: kdeglobals, gtk3/4-settings, qt5ct
- "Add a zsh alias" → Edit `default/zsh/solverforge-aliases.zsh`
- "Wire a new config through the framework" → Template → generate → symlink → reload. Beautiful linking.
